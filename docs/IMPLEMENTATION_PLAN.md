# План реализации

## Текущий статус

Репозиторий содержит завершённую **архитектуру MVP-предпросмотра**:

| Область | Статус | Примечания |
| --- | --- | --- |
| Многослойное решение и DI-композиция | Готово | Domain, Application, Infrastructure, Desktop |
| Модели и контракты предметной области | Готово | Неизменяемые; строгий nullable включён |
| Математика выравнивания | Готово | Покрыта юнит-тестами |
| Адаптер Demucs | Готово | Разбор прогресса, отмена, обнаружение вывода |
| Анализ аудио | Готово | Декодирование FFmpeg + управляемый DSP темпа/даунбита/хромы |
| Адаптер FFmpeg Rubber Band | Готово | Машиночитаемый прогресс, понятная ошибка при отсутствии фильтра |
| Главная ViewModel и команды | Готово | Асинхронные, отменяемые, задержка точной высоты тона, локализованные ошибки |
| Редакционный светлый UI | Готово | Монохромная система; светлая, тёмная и системная темы |
| Локализация RU/EN во время работы | Готово | Живые привязки XAML, локализованное состояние VM, язык системы по умолчанию |
| Поиск и загрузка с YouTube | Готово | yt-dlp + FFmpeg, cookies браузера или cookies.txt, миниатюры и прогресс |
| Синхронный предпросмотр ManagedBass | Готово | Требуется развёртывание нативного BASS |
| Автоматические тесты | Готово | 78 тестов |
| Реальное извлечение волновой формы | Готово | `FfmpegWaveformService` и общая свёртка пиков |
| Экспорт сведения | Готово | `FfmpegMixdownService`: `amix`, громкости, смещение, WAV |
| Установщик/упаковка | Запланировано | Внешние инструменты устанавливаются вручную |

Сборка и тесты проходят на `net8.0`.

## 1. План этапов

### Этап 0 — Основа проекта

Результаты:

- решение и проекты слоёв,
- центральные настройки nullable/сборки,
- оболочка Avalonia, DI-композиция,
- структурированные контракты ошибок и прогресса.

Критерии приёмки:

- `dotnet build` успешен с предупреждениями как ошибками,
- приложение запускается в пустое состояние,
- Domain/Application не ссылаются на слой UI.

Статус: **завершён**.

### Этап 1 — Предметная область и контракты

Результаты:

- `AudioTrack`, `TrackMetadata`, `MusicalKey`,
- `StemSeparationResult`, `AlignmentParameters`, `AlignmentPlan`,
- `AudioAnalysisResult`, `OperationProgress`,
- интерфейсы сервисов,
- тесты выравнивания и транспозиции тональности.

Критерии приёмки:

- детерминированные тесты предметной области,
- все параметры валидируются,
- в контрактах нет типов внешних инструментов.

Статус: **завершён**.

### Этап 2 — Слой внешних процессов

Результаты:

- `ProcessRunner` с `ArgumentList`, одновременным чтением потоков, убийством дерева при отмене,
- ограниченный диагностический хвост,
- фабрика рабочих областей с уникальными временными каталогами и проверками путей.

Критерии приёмки:

- нет выполнения через оболочку,
- отмена процесса возвращается быстро и удаляет частичный вывод,
- нет взаимных блокировок при шумном stderr.

Статус: **завершён**.

### Этап 3 — Разделение Demucs

Результаты:

- аргументы CLI для двух потоков `htdemucs`,
- приведение прогресса tqdm,
- обнаружение результата,
- юнит-тест с подставным исполнителем.

Критерии приёмки:

- возвращается ровно один вокальный и один инструментальный стем,
- прогресс никогда не уменьшается,
- отмена убивает дерево процессов Demucs,
- ошибки содержат полезный хвост вывода инструмента.

Статус: **завершён**.

### Этап 4 — Анализ

Результаты:

- декодирование моно PCM через FFmpeg,
- FFT,
- определение темпа и фазы доли по спектральному потоку,
- позиция даунбита 4/4,
- определение тональности по хроме и отображение в Кэмелот,
- синтетический тест темпа.

Критерии приёмки:

- синтетический клик-трек 120 BPM определяется с точностью ±1 BPM,
- математика тональности даёт корректные значения Кэмелота,
- DSP выполняется вне потока UI,
- ошибки декодирования явные.

Статус: **завершён**.

### Этап 5 — Рабочий процесс и рендеринг

Результаты:

- `MashupWorkflow`,
- агрегация прогресса,
- команда FFmpeg Rubber Band,
- валидация рендеринга и разбор прогресса,
- путь повторного рендеринга при точной высоте тона.

Критерии приёмки:

- сквозные результаты — непустые WAV-стемы,
- порядок этапов корректен,
- длительность вывода приблизительно равна `sourceDuration / tempoRatio`,
- отсутствие фильтра Rubber Band даёт понятную инструкцию.

Статус: **завершён**, ожидаются интеграционные тесты на медиафайлах.

### Этап 6 — Воспроизведение

Результаты:

- плеер ManagedBass с двумя потоками,
- управление громкостью на лету,
- изменение смещения на лету,
- монитор отложенного старта вокала,
- обнаружение окончания,
- команды транспорта VM и таймер курсора.

Критерии приёмки:

- Play/Pause/Stop детерминированы,
- подстройка ±5 с даёт ожидаемое опережение/задержку вокала,
- сбой плеера не уничтожает подготовленные файлы и не роняет приложение,
- поток UI не блокируется.

Статус: **завершён**, требуется развёртывание нативного BASS для проверки во время работы на каждой ОС.

### Этап 7 — Редакционный редизайн

Результаты:

- система токенов/стилей `Theme.axaml` и `AppStyles.axaml`,
- разделение оболочки `MainWindow` и рабочего пространства `MainView`,
- монохромная палитра с границами 1 px и радиусами 4–6 px,
- плоские основные/контурные/сегментированные кнопки, без теней, свечений и градиентов,
- системная/светлая/тёмная темы с системной по умолчанию,
- переработанные дорожки волновой формы и транспорт,
- локализованные тексты на английском и русском.

Критерии приёмки:

- весь видимый UI следует палитре и ограничениям радиусов,
- используются только скомпилированные привязки,
- состояния пустоты/обработки/готовности/ошибки/воспроизведения читаемы,
- переключение RU/EN мгновенное и сохраняет навигацию/состояние,
- ни один пользовательский текст не остаётся жёстко заданным на английском, если для него есть ключ локализации.

Статус: **завершён**; проверено визуально на обоих языках.

### Этап 8 — Загрузка с YouTube и локализация

Результаты:

- `ILocalizationService`, синглтон `LocalizationManager`, `LocalizeExtension`,
- `Strings.en.json` / `Strings.ru.json`,
- `IYouTubeTrackService` и `YtDlpTrackService` на десктопе,
- автоматический поиск Deno/Node.js/Bun для yt-dlp,
- fallback на cookies браузера при проверке «Sign in to confirm you're not a bot»,
- выбор пользовательского `cookies.txt` прямо в диалоге YouTube и автоповтор загрузки,
- загрузка миниатюр, поиск с задержкой и отменой, встроенный прогресс,
- модальный `YouTubeSearchDialog` с назначением дорожке A / дорожке B,
- передача метаданных в `AudioTrack`.

Критерии приёмки:

- поиск по Enter и по вводу с задержкой,
- `yt-dlp` скачивает лучший аудиопоток, FFmpeg конвертирует в PCM WAV,
- ошибки `yt-dlp` и FFmpeg показываются локализованно,
- закрытие диалога отменяет извлечение и не оставляет частичный файл,
- выбор результата заполняет целевую дорожку названием, автором и длительностью.

Статус: **завершён**; поиск, загрузка, конвертация, назначение и состояния ошибок проверены во время работы на реальном видео.

## 2. Следующий релиз: подготовка к продакшену

Рекомендуемый порядок:

1. **Реальные пики волновой формы — реализовано**
   - `IAudioWaveformService.ExtractPeaksAsync(filePath, buckets, ct)`.
   - `FfmpegWaveformService` декодирует моно 8 кГц и сворачивает оконные пики.
   - Таймлайн и оба диалога привязаны к `WaveformView.Peaks`; при сбое остаётся нейтральный макет.
   - Осталось: кэширование пиков между повторными рендерами и переход по клику.

2. **Экспорт сведения — реализовано**
   - `IMixdownService` и `FfmpegMixdownService`: громкости, задержка/обрезка вокала, `amix`, WAV 48 кГц.
   - Диалог сохранения через storage provider Avalonia и кнопка «Скачать микс».
   - Осталось: лимитер/нормализация и экспорт в MP3/FLAC.

3. **Ручные переопределения и UI уверенности**
   - Редактируемые BPM, первый даунбит и тональность.
   - Отображение уверенности анализа.
   - Элементы сброса к автоматическим значениям.
   - Приёмка: намеренно неверно определённые треки можно исправить без редактирования файлов.

4. **Проход по качеству анализа**
   - Тестировать на подобранном наборе файлов разных жанров.
   - Настроить приор темпа, обработку половинного/двойного темпа, определение даунбита и профили тональности.
   - Рассмотреть адаптер Essentia, если точность останется недостаточной.
   - Приёмка: согласованные пороги бенчмарка (например, BPM в пределах 1 %, тональность в топ-2 попадает в набор).

5. **Измерение и коррекция дрейфа воспроизведения**
   - Измерить дрейф двух потоков в Windows/Linux/macOS.
   - При необходимости перейти на микшер BASS или периодическую синхронизацию с малым усилением.
   - Приёмка: нет слышимого дрейфа за 10 минут.

6. **Упаковка и проверка зависимостей**
   - Проверка зависимостей при запуске для FFmpeg/rubberband, Demucs, BASS.
   - Подписанные установщики (для каждой ОС), UI настроек путей к инструментам.
   - Матрица CI для `win-x64`, `linux-x64`, `osx-arm64`; тесты не зависят от отсутствия нативных инструментов.
   - Приёмка: на чистой машине пользователь получает понятную ошибку, а на настроенной — может пройти весь рабочий процесс.

7. **Сохранение и восстановление**
   - Сохранять JSON проекта рядом с выбранной папкой проекта или в данных приложения.
   - Переиспользовать уже разделённые стемы при повторном открытии.
   - Очищать осиротевшие рабочие области при запуске.
   - Приёмка: закрытие/повторное открытие восстанавливает дорожки и выравнивание.

8. **Доступность и UX**
   - Горячие клавиши, доступные имена для кнопок только с иконками.
   - Состояния фокуса и проверка высокой контрастности.
   - Реальная прокрутка/перемотка волновой формы и скелетон загрузки.

## 4. Критерии приёмки сквозного мэшапа

Для любых двух поддерживаемых локальных файлов и корректно установленных зависимостей:

1. Приложение создаёт инструментал дорожки A и вокал дорожки B в формате WAV.
2. Обе исходные дорожки отображают BPM, даунбит и тональность.
3. Выровненный вокал рендерится с допуском ±2 % от отношения длительности источника к коэффициенту темпа.
4. Предпросмотр начинается со смещением вокала, ожидаемым по расчёту даунбита.
5. Изменения громкости независимы.
6. Подстройка в пределах ±5 с меняет синхронизацию в реальном времени.
7. UI остаётся отзывчивым, все операции можно отменить.
8. Ни один частичный результат не выдаётся за успешный.

## 5. Риски и меры снижения

| Риск | Влияние | Мера |
| --- | --- | --- |
| Большая установка/загрузка модели Demucs | Сложность первого запуска | Инструкция при запуске; закреплённая модель; позже необязательный установщик |
| В сборке FFmpeg нет librubberband | Нет рендеринга | Предварительная проверка + понятная ошибка; документировать требование к проверенной сборке |
| Нативная библиотека/лицензия BASS | Нет воспроизведения | Ленивая ошибка, необязательное воспроизведение, документация по развёртыванию, проверка лицензии |
| Ошибки октавы темпа | Неверная длина вокала | UI уверенности BPM, ручное переопределение, защита диапазона |
| Несовпадение даунбита | Вокал вступает не в долю | Ползунок подстройки, в будущем UI сетки тактов/долей |
| Неоднозначность тональности (параллельные тональности) | Неверный план высоты тона | Правило нулевого сдвига для параллельных тональностей, точная высота тона, будущее ручное переопределение |
| Дрейф синхронизации двух потоков | Слышимый рассинхрон | Инструментал как ведущие часы; измеренная коррекция в будущем |
| Давление на память GPU в Demucs | Сбой на слабых машинах | Последовательные задания, настраиваемые устройство/задания, явная диагностика |
| Рост временного хранилища | Использование диска | Уникальные рабочие области, освобождение при новой сессии/выходе, очистка при запуске в будущем |
| Проверка «Sign in to confirm you're not a bot» в yt-dlp | Загрузка YouTube может требовать JS-runtime и cookies | Автопоиск Deno/Node.js/Bun, fallback на cookies браузера по умолчанию, выбор cookies.txt, понятная локализованная ошибка и повторная попытка |
| Ломающие изменения/лимиты YouTube | Сбои поиска или загрузки | Типизированные ошибки, отменяемые запросы, изолированный порт для альтернативного провайдера, обновляемый yt-dlp |
| Защищённый авторским правом контент YouTube | Юридический риск для пользователей | Встроенное предупреждение; ответственность за права несёт владелец |
| Отсутствующие ключи локализации | Смешанный язык UI | Проверка паритета ключей в CI; откат на английский |
| Нестабильность оформления заголовка Windows | Визуальная несогласованность | Принятие нативного оформления; целевой дизайн — светлая тема клиентской области |
