# MusicMixer — студия мэшапов

[![CI](https://github.com/zana052010/Music-Mixer/actions/workflows/ci.yml/badge.svg)](https://github.com/zana052010/Music-Mixer/actions/workflows/ci.yml)

Музыкальная рабочая станция на Avalonia для создания мэшапов «вокал поверх инструментала». Приложение работает на Windows, Linux и macOS.

- **Дорожка A** разделяется на инструментальный стем.
- **Дорожка B** разделяется на вокальный стем.
- Обе дорожки анализируются на **BPM**, смещение первой доли такта **4/4** и **тональность / нотацию Кэмелота**.
- Вокал приводится к темпу и тональности инструментала с помощью **FFmpeg + librubberband**.
- Синхронный предпросмотр двух потоков воспроизводится через **ManagedBass**.
- Обе исходные дорожки можно загружать из локальных файлов или искать на **YouTube** через встроенную библиотеку **YoutubeExplode** с конвертацией в WAV через FFmpeg.
- Каждый источник можно **обрезать в отдельном диалоге прослушивания**; выбранный диапазон рендерится до анализа и разделения.
- Волновые формы в таймлайне, окне прослушивания и редакторе обрезки строятся по **реальным пикам** аудио. Декодирование выполняется в фоне, поэтому интерфейс не блокируется.
- После разделения инструментал и вокал автоматически **улучшаются**: мягкий high-pass, EQ, компрессия и лимитер убирают гул и муть и добавляют разборчивость. Улучшение можно отключить перед сборкой.
- Кнопка между карточками **меняет инструментал и вокал местами**; готовый микс после этого нужно собрать заново.
- Скорость вокала можно **переопределить вручную** ползунком (0.5–2.0×), вернуть автоматическое значение по BPM или нейтральные 1.0×.
- Готовый мэшап можно **сохранить в WAV** кнопкой «Скачать микс» в нижней части таймлайна: инструментал и вокал сводятся с текущими громкостями и смещением. Кнопка «Обрезать и скачать» сначала даёт выбрать фрагмент уже сведённого микса, а затем сохраняет его.
- Интерфейс мгновенно переключается между **английским и русским** языками.
- Визуальная система — монохромный интерфейс, вдохновлённый **shadcn/ui**, с мгновенным переключением **системной, светлой и тёмной темы**. По умолчанию приложение следует теме операционной системы.

> Репозиторий собирается, и тесты запускаются без внешних инструментов. Обработка аудио, загрузка с YouTube и воспроизведение требуют внешних зависимостей, перечисленных ниже.

## Предварительные требования

### 1. .NET

- **Десктоп:** .NET 8 SDK (проекты нацелены на `net8.0`). Windows, Linux или macOS.

### 2. FFmpeg с librubberband

Рендерер вокала вызывает:

```text
ffmpeg -af "rubberband=tempo=...:pitch=..."
```

Убедитесь, что ваш бинарник FFmpeg содержит этот фильтр:

```bash
ffmpeg -hide_banner -filters | grep rubberband
```

В Windows PowerShell:

```powershell
ffmpeg -hide_banner -filters | Select-String rubberband
```

Если фильтр отсутствует, используйте сборку FFmpeg, скомпилированную с `--enable-librubberband` (лицензирование зависит от сборки и модели распространения). Приложение сообщает понятную ошибку вместо незаметного ухудшения качества.

### Локальный FFmpeg в проекте (без изменений системного PATH)

Поместите бинарник внутрь репозитория:

```text
tools\ffmpeg\bin\ffmpeg.exe
```

`MusicMixer.Desktop.csproj` копирует его в выходной каталог приложения, а `FfmpegOptions.FromEnvironment()` автоматически обнаруживает его в `tools\ffmpeg\bin` или рядом с исполняемым файлом. Достаточно локальной сборки Gyan Essentials, если в её конфигурации есть `librubberband`; всегда проверяйте это командой для фильтра выше.

Порядок поиска:

1. `MUSICMIXER_FFMPEG`
2. встроенный `<app>/tools/ffmpeg/bin/ffmpeg[.exe]`
3. `<app>/ffmpeg[.exe]`
4. `ffmpeg` из `PATH`

Для локальной установки в проекте вручную задавать переменную окружения не нужно.

### 3. Demucs

Demucs вызывается как дочерний процесс в режиме двух стемов (`htdemucs` по умолчанию).

```bash
python -m pip install --upgrade demucs
demucs --help
```

При первом разделении скачивается модель `htdemucs`. Локальное окружение проекта автоматически обнаруживается десктопным приложением:

```text
<repo>\.venv\Scripts\demucs.exe
```

Хост также добавляет каталог найденного FFmpeg в начало `PATH` дочернего процесса, чтобы Demucs мог вызывать `ffmpeg` и `ffprobe`. Если Demucs установлен в другом месте, задайте:

```powershell
$env:MUSICMIXER_DEMUCS = "C:\path\to\.venv\Scripts\demucs.exe"
```

Необязательные переопределения:

| Переменная окружения | Значение |
| --- | --- |
| `MUSICMIXER_FFMPEG` | Абсолютный путь к `ffmpeg` |
| `MUSICMIXER_DEMUCS` | Абсолютный путь к `demucs` |
| `MUSICMIXER_DEMUCS_MODEL` | Модель Demucs, по умолчанию `htdemucs` |
| `MUSICMIXER_DEMUCS_DEVICE` | `cpu`, `cuda`, `mps` и т. п. |

### 4. Поиск и загрузка с YouTube

На десктопе YouTube работает через библиотеку **[YoutubeExplode](https://github.com/Tyrrrz/YoutubeExplode)** прямо внутри приложения — отдельные программы (yt-dlp, Deno, Node.js) больше не нужны. Поиск выдаёт до 15 видео, выбранное аудио скачивается в лучшем доступном качестве «только аудио», а тот же FFmpeg, что используется остальным конвейером, конвертирует его в WAV PCM 48 кГц.

Если YouTube требует подтвердить вход («Sign in to confirm you're not a bot») или ограничивает запросы, подключите cookies `youtube.com` в формате Netscape:

- в диалоге YouTube нажмите **«Выбрать cookies.txt»** — файл действует до конца сессии, а неудачная загрузка сразу повторится;
- или задайте путь заранее:

```powershell
$env:MUSICMIXER_YOUTUBE_COOKIES = "C:\path\to\cookies.txt"
```

Старая переменная `MUSICMIXER_YTDLP_COOKIES` тоже читается для совместимости. Cookies — это данные вашей учётной записи; используйте отдельный профиль или тестовый аккаунт, если не хотите передавать основной.

YoutubeExplode разбирает внутреннее API YouTube и обновляется реже, чем yt-dlp. Если YouTube изменит формат, поиск или загрузка могут временно перестать работать до выхода новой версии библиотеки. На странице пакета указано, что он ограниченно доступен в России и Беларуси.

Проект намеренно скрывает YouTube за `IYouTubeTrackService`: реализация — `YoutubeExplodeTrackService`. Другого провайдера или адаптер YouTube Data API можно подставить, не затрагивая движок мэшапа или UI.

### 5. Нативная библиотека BASS

`ManagedBass` — управляемая обёртка; сам BASS нативный. Нативный бинарник не хранится в репозитории, но десктопный проект копирует локальную установку в выходной каталог сборки.

Скачайте 64-битный пакет BASS с [un4seen.com](https://www.un4seen.com/), распакуйте и поместите библиотеку сюда:

```text
tools\bass\x64\bass.dll
```

`MusicMixer.Desktop.csproj` автоматически копирует её в каталог приложения. Если файл отсутствует, установите соответствующую нативную библиотеку рядом с приложением или в путь поиска нативных библиотек:

| Платформа | Библиотека |
| --- | --- |
| Windows x64 | `bass.dll` |
| Linux x64 | `libbass.so` |
| macOS arm64/x64 | `libbass.dylib` |

Пути воспроизведения, прослушивания и предпросмотра обрезки используют базовую библиотеку BASS; обработанные стемы — это PCM WAV. Лицензирование BASS отдельно от этого репозитория: оно бесплатно для некоммерческого использования и требует коммерческой лицензии в остальных случаях. Не распространяйте нативный бинарник, не проверив лицензию.

Если BASS недоступен, подготовка всё равно завершается, но предпросмотр, окно прослушивания и редактор обрезки недоступны, поскольку им нужен движок предпросмотра.

## Сборка и запуск

```bash
dotnet restore
dotnet build MusicMixer.sln
dotnet test MusicMixer.sln
dotnet run --project src/MusicMixer.Desktop
```

Сборка Release:

```bash
dotnet publish src/MusicMixer.Desktop/MusicMixer.Desktop.csproj -c Release -r win-x64 --self-contained false
```

При необходимости используйте `linux-x64`, `osx-x64` или `osx-arm64`.

Готовые сборки в репозитории не хранятся: каталоги `dist/` и `publish/` указаны в `.gitignore`. Соберите приложение командой выше или скачайте архив из [GitHub Releases](https://github.com/zana052010/Music-Mixer/releases), если он там опубликован. Если перед сборкой положить `ffmpeg`, `ffprobe` и `bass.dll` в каталог `tools/`, они будут скопированы рядом с приложением. Для запуска нужен .NET 8 Runtime, а для разделения стемов — установленный Demucs.

## Рабочий процесс

1. Загрузите дорожки A и B:
   - перетащите локальный файл или нажмите **Выбрать файл**. Выбранный источник сначала открывается в **окне прослушивания**. Прослушайте, перемотайте трек и нажмите **Добавить трек**, чтобы поместить его в слот, или **Отмена**, чтобы оставить слот без изменений.
   - нажмите **YOUTUBE**, выполните поиск и выберите **В мелодию (A)** или **В вокал (B)**. После загрузки трек открывается в том же окне прослушивания; прослушайте и подтвердите, прежде чем добавлять его в слот.
2. При необходимости нажмите **Обрезать** на карточке любого источника:
   - воспроизведите оригинал, перемотайте по таймлайну и задайте **НАЧАЛО** и **КОНЕЦ** кнопками **Начало здесь** и **Конец здесь**,
   - нажмите **Прослушать выбранное**, чтобы прослушать только выбранный фрагмент,
   - нажмите **Применить обрезку**. Приложение рендерит WAV PCM 48 кГц с точностью до сэмпла для выбранного диапазона до анализа и разделения.
3. Нажмите **Собрать мэшап**.
4. Приложение:
   - анализирует оба выбранных источника,
   - запускает Demucs для дорожки A и дорожки B,
   - выравнивает даунбит дорожки B по сетке дорожки A,
   - вычисляет транспозицию тональности и коэффициент растяжения по времени,
   - рендерит WAV PCM 48 кГц, стерео, преобразованного вокала,
   - строит реальные пики волновой формы для инструментала и готового вокала.
5. Нажмите **Играть** для синхронного предпросмотра двух потоков.
6. Перетаскивайте ползунок перемотки под дорожками волновой формы, чтобы перейти к любому моменту подготовленного мэшапа — на паузе или во время воспроизведения.
7. Настройте:
   - **ТОН · ТОЧНО** (`-2`…`+2` полутона) — запускает повторный рендеринг с задержкой.
   - **СМЕЩЕНИЕ · СИНХРО** (`-5 с`…`+5 с`) — применяется плеером на лету.
   - **ИНСТРУМЕНТАЛ / ВОКАЛ** в блоке **ГРОМКОСТЬ** — применяется на лету.
8. Нажмите **Скачать микс**, выберите папку и имя файла. Приложение сведёт инструментал и выровненный вокал в WAV PCM 48 кГц/стерео с теми громкостями и смещением, которые вы слышите в предпросмотре.

Интерфейс остаётся отзывчивым; все внешние процессы, DSP-обработка и рендеринг можно отменить.

## Локализация во время работы

- `LocalizationManager` — синглтон, реализующий `ILocalizationService`.
- `Strings.en.json` и `Strings.ru.json` — встроенные ресурсы Avalonia с одинаковым набором ключей.
- В XAML используется `{loc:Localize Key=...}`. Расширение разметки привязывает каждый текстовый элемент к стабильному `LocalizedString`, который вызывает `PropertyChanged` при смене языка.
- Сообщения состояния и ошибки во view-model хранят ключи локализации, поэтому переключение языка обновляет и активный текст прогресса, и текст ошибок.
- Используйте сегментированный переключатель `EN | RU` в шапке. Переключение мгновенное, не пересоздаёт окно и не теряет текущую сессию.
- При запуске приложение следует языку интерфейса операционной системы, с откатом на английский.

## Математика выравнивания

Чистая реализация предметной области находится в [AlignmentCalculator.cs](src/MusicMixer.Domain/Alignment/AlignmentCalculator.cs) и [KeyTransposition.cs](src/MusicMixer.Domain/Alignment/KeyTransposition.cs).

```text
tempoRatio = BPM_instrumental / BPM_vocal
pitchShift = shortestKeyShift(vocal.Key -> instrumental.Key) + finePitch
automaticOffset = instrumental.DownbeatOffset
                - (vocal.DownbeatOffset * tempoRatio)
finalOffset = automaticOffset + nudge
```

Параллельные мажор/минор считаются совместимыми и не получают автоматического сдвига тональности. Это сохраняет естественный диапазон вокала, удерживая его в том же звукоряде. В остальных случаях используется наименьшая знаковая транспозиция тоники. Музыкальное обоснование и ограничения см. в документе об архитектуре.

## Тесты

Набор тестов покрывает:

- расчёты выравнивания и математику смещения даунбита,
- нотацию Кэмелота и транспозицию тональности,
- валидацию параметров,
- обнаружение стемов Demucs и приведение прогресса,
- пик radix-2 FFT,
- детекцию BPM на синтетическом клик-треке,
- порядок этапов рабочего процесса, прогресс и оркестрацию повторного рендеринга при точной подстройке с использованием подставных объектов,
- сборку фильтра сведения (`amix`, задержка/обрезка вокала, громкости) и публикацию готового WAV,
- проверку id видео, разбор `cookies.txt` в формате Netscape и классификацию ошибок YouTube,
- отказ до скачивания, если FFmpeg недоступен, и проверку, что результат загрузки — только `.wav`,
- свёртку оконных пиков волновой формы, нормировку и устойчивость к тишине/некорректным значениям,
- паритет ключей локализации английского и русского языков.

## Известные ограничения и дальнейшие шаги

- Анализ даунбита и тональности эвристический и предполагает музыку 4/4. Точная высота тона и сдвиг синхронизации — предусмотренные способы ручной коррекции. Ручное переопределение BPM/тональности — следующий шаг.
- Если детектор темпа ошибся на октаву (60 против 120 BPM), отношение темпа автоматически приводится к ближайшей допустимой октаве, чтобы мэшап можно было собрать.
- Анализ читает не более первых 10 минут файла (`AudioAnalysisOptions.MaxDuration`). Demucs обрабатывает весь выбранный источник.
- Дорожки волновой формы строятся по реальным пикам через FFmpeg. Если декодер не смог построить волну, интерфейс показывает нейтральный макет и не прерывает подготовку мэшапа.
- Предпросмотр в окнах прослушивания и обрезки использует BASS напрямую, поэтому охват форматов определяется установленной сборкой BASS и кодеками ОС. Поддерживаются MP3, WAV, OGG и распространённые форматы Windows Media Foundation; для необычных кодеков может потребоваться дополнение BASS.
- Экспорт сохраняет готовый микс в WAV PCM 48 кГц/стерео и требует FFmpeg. Другие форматы (MP3, FLAC) пока не экспортируются.
- Изменение точной высоты тона повторно рендерит вокал через FFmpeg и ненадолго приостанавливает предпросмотр. Это сделано намеренно: предпросмотр никогда не должен незаметно расходиться с отрендеренным стемом.
- Синхронизация двух потоков использует инструментал как ведущие часы. Громкость и начальное смещение синхронизируются; коррекция дрейфа на длинных сессиях отложена до измерений на целевых машинах.
- BASS необязателен при сборке, но необходим для воспроизведения.
- YouTube работает через библиотеку YoutubeExplode. Скачивайте только тот контент, на который у вас есть права.
- YouTube может вернуть `VideoUnavailable`, ограничить запросы или потребовать проверку «Sign in to confirm you're not a bot». В этом случае выберите `cookies.txt` в диалоге YouTube или задайте `MUSICMIXER_YOUTUBE_COOKIES`. YoutubeExplode обновляется реже, чем yt-dlp, поэтому после изменений на стороне YouTube загрузка может временно не работать. Приложение объясняет причину и оставляет элемент доступным для повторной попытки.
- Загрузка с YouTube проверяет FFmpeg перед скачиванием, поэтому отсутствующий/сломанный FFmpeg обнаруживается сразу, а не после большой загрузки. FFmpeg нужен для конвертации в WAV, хотя для самого поиска достаточно сетевого доступа.
